# 劇情文本工具鏈：原理、產出與驗證

> 適用：Windows、R18 WebGL catalog、繁體中文 `zh_Hant.json`
> 原則：每次更新建立獨立日期資料夾；不使用翻譯 API；人工確認後才同步 Git repo。

**先讀同層的 `README.md`**（環境安裝、一鍵指令、參數覆寫）。本檔接在它後面，
只寫 README 沒有的東西：腳本每一步在做什麼、產出怎麼看、怎麼驗、怎麼同步回 repo、
以及踩過的錯誤。

> 這是「A 產線」。UI／系統文字是「B 產線」，見上層 `HANDOVER.md`。
> **兩條都做完才算一次完整更新。**

⚠️ **本檔曾經寫滿原作者本機的絕對路徑**（`E:\離線板\files`、
`D:\dotabyss-translation\...\-X-`）。工具鏈早已改成以腳本位置自動推導，
clone 下來直接能跑；那些路徑在別台電腦一律不存在，已全部改成 repo 相對寫法。
若在舊 commit 上工作才會看到舊寫法。

## 1. 工具各自負責什麼

全部在同層 `tools/`，`OfficialNovelUpdate.ps1` 會依序呼叫：

| 檔案 | 用途 |
|---|---|
| `OfficialNovelUpdate.ps1` | 一鍵入口，依序跑完下面所有階段 |
| `FetchLatestCatalogOnly.py` | 抓最新版 R18 MasterData、catalog、`assets.json` |
| `PrepareTextNovelDownloadManifest.py` | 只建立小說文本 bundle 清單 |
| `DownloadCatalogBundles.py` | 下載清單中的 bundle，支援續傳與重試 |
| `ExportCatalogNovelTexts.py` | 解出 `novels_all`、`zh_Hant.json` 與官方原始 TXT |
| `FillPendingFromTranslationMemory.py` | 依**完全相同**的日文 key 套用既有翻譯 |
| `FindEmptyNovelTranslations.py` | 產生空值 CSV／Markdown／HTML 報告 |
| `CopyPendingNovelFolders.py` | 複製所有仍有空值的資料夾 |
| `CopyNovelFoldersMissingFromRepo.py` | 只列出所有來源都沒有的全新資料夾 |
| `ValidatePendingNovelTranslations.py` | 檢查 JSON、空值、標籤與高風險用語 |

> 原作者另有一套 Unity 離線播放器（另一台機器的獨立專案）。
> **那跟本 repo 是兩件事**：離線播放器用官方劇本 TXT 與自己的翻譯表，
> 不要把 repo 的 `zh_Hant.json` 直接塞進去。先做完 repo 文本，再另開批次處理它。

## 2. 腳本依序做了什麼

1. 從官方 R18 端點取得版本資訊。
2. 下載 MasterData 與 `catalog_1.bin`。
3. 解析 catalog 為 `assets.json`。
4. 只建立小說文本 bundle manifest。
5. 只下載小說文本，不下載全部遊戲資源。
6. 解出最新官方日文 key、`zh_Hant.json`、官方原始 TXT。
7. 從既有 novels 來源依日文 key 套用翻譯記憶（來源清單見 `README.md`）。
8. 找出仍為空字串的 value。
9. 產生待處理資料夾與「純全新資料夾」清單。
10. 比較上一個 `official_update_*` 的 L2D ID。

### 為什麼不能只比對資料夾名稱

官方會**修改既有腳本裡的一句原文**：刪掉或增加一小段、同一句少一個詞、
漢字寫法換成假名。這時資料夾名稱不變，單純比對資料夾會整句漏掉。

所以流程是先建立「官方最新 key ＋ repo 既有翻譯」，凡是 repo 沒有**完全相同 key**
的句子都保持 `""`——舊腳本改字因此也會出現在 `pending_novels`。

## 3. 產出結構

在 `<BaseDir>\output\official_update_<日期>\`（`BaseDir` 預設在 repo 外，不污染版控）：

| 路徑 | 用途 |
|---|---|
| `latest_catalog_info.json` | 官方資產版、MasterData 版、下載 URL、catalog hash |
| `catalog_1.bin` / `assets.json` | 當次官方 catalog 原檔與解析結果 |
| `text_novel_manifest.csv` | 本次小說文本下載清單 |
| `text_novel_downloads` | 原始 Unity 文本 bundle |
| `novels_all` | 官方最新 key，並已套用可沿用的舊翻譯 |
| `novel_text_raw` | 官方完整劇本指令 TXT，含動作、音訊、角色命令 |
| `pending_novels` | **要翻的東西**：所有仍含空值的資料夾（含新資料夾及舊腳本改字） |
| `new_folders_only` | 所有比對來源都沒有的全新資料夾 |
| `empty_translations` | 空值 CSV、MD、HTML 報告 |
| `pending_translation_stats.csv` | 每個待翻資料夾的條數統計 |
| `pending_validation.txt` | JSON、標籤、用語初步驗證 |
| `l2d_changes.txt` | 相對上一版新增／移除的 L2D ID |

### 成功標準

- `download_failed.txt` 為空。
- `novel_export_summary.json`：`missing_bundles = 0`、`failed_bundles = 0`。
- `pending_novels\index.json` 可正常開啟。
- `pending_validation.txt` 沒有 parse error 或 tag error。

## 4. 翻譯

只編輯 `pending_novels\<script_id>\zh_Hant.json`：

```json
{
  "日文原文 key": "繁體中文翻譯 value",
  "新出現的日文": ""
}
```

**譯文風格、術語、角色語氣一律照上層 `translation_rules.md`**（唯一來源）。
這條產線另外三條規則：

1. **只改 value，不改日文 key**（差一個字元就永遠命不中，見 `HANDOVER.md` 陷阱二）。
2. 不新增 `zh_Hans.json`。
3. 不使用翻譯 API 自動補翻；不要執行舊版的 `AutoTranslate.py`。

譯名以本 repo `names/zh_Hant.json` 為最高優先；新增譯名要同步補進去。

---

## 5. 翻完後驗證

```powershell
$date   = "<日期>"
$root   = "<BaseDir>\output\official_update_$date"
$tools  = "<這個資料夾>\tools"
$python = "$tools\.venv\Scripts\python.exe"
```

檢查空值：

```powershell
& $python "$tools\FindEmptyNovelTranslations.py" `
  --novels "$root\pending_novels" `
  --output "$root\final_empty_check" `
  --lang zh_Hant.json
```

完整驗證：

```powershell
& $python "$tools\ValidatePendingNovelTranslations.py" --novels "$root\pending_novels"
```

放行條件：`empty=0`、`parse_errors=0`、`tag_errors=0`、高風險詞逐條人工確認完畢。

## 6. 同步回 repo

把翻好的資料夾放回**來源**目錄，**依是否已上線分流**：

| 目的地 | 什麼情況 |
|---|---|
| `novels/` | 已上線 |
| `novels_untranslated_only/` | 尚未上線（`new_folders_only` 多半屬此） |

只搬你動過的資料夾，不要整包覆蓋。

```powershell
$date    = "<日期>"
$pending = "<BaseDir>\output\official_update_$date\pending_novels"
$repo    = "<本 repo>\dotabyss-translation-client-version-s88037zz\novels"

Get-ChildItem -LiteralPath $pending -Directory | ForEach-Object {
    $source    = Join-Path $_.FullName "zh_Hant.json"
    $targetDir = Join-Path $repo $_.Name
    if (Test-Path -LiteralPath $source) {
        New-Item -ItemType Directory -Path $targetDir -Force | Out-Null
        Copy-Item -LiteralPath $source -Destination (Join-Path $targetDir "zh_Hant.json") -Force
    }
}
```

確認 `git status --short` 只包含預期的 `novels/*/zh_Hant.json` 與 `names/zh_Hant.json`
後再逐檔 `git add`（本 repo 禁用 `git add -A`，上層有未追蹤的 `.zip` 與 TEST 資料夾）。
不要把 `assets.json`、catalog、bundle、整個 `output` 提交進 repo。

> 🩸 **最容易漏的一步**：本工具鏈**不會動 manifest**。劇情進了 repo 之後，
> 一定要回上層 `HANDOVER.md` 第 3 節重建分包（`build_novels_all.py`）、
> 更新 manifest，並在 push 後跑 `verify_cdn.py` 驗 CDN，否則玩家拿不到。

## 7. 保留指定文本

官方可能把預載內容撤下，重要文本要另存於當次版本資料夾：

```text
preserved_novel_texts/
├─ novels/        # zh_Hant.json
└─ official_raw/  # 官方完整 TXT
```

角色場景 ID 慣例：

- `hmr_角色ID00011`：開場／銜接
- `hmr_角色ID00012`：主要 L2D 場景
- `hmr_角色ID00013`：收尾
- 第二、三組則為 `21～23`、`31～33`

只保存 `12／22／32` 得到的是三段主要 L2D 文本；要完整劇情就得連
`11～13／21～23／31～33` 一起保存。

## 8. 常見錯誤

| 症狀 | 處理 |
|---|---|
| `ModuleNotFoundError: requests / UnityPy / msgpack / Crypto / rich` | venv 沒建好或沒用到，重跑 `README.md` 的安裝指令 |
| `OPENAI_API_KEY is not set` 或 API 429 | 正式流程不使用 API，不要執行 `AutoTranslate.py` 或舊版自動翻譯階段 |
| `download_failed.txt` 有內容 | 用**完全相同**的 `DownloadCatalogBundles.py` 指令重跑；已完成且大小正確的檔會自動跳過 |
| `MasterData.json` 找不到 | 確認跑的是 `FetchLatestCatalogOnly.py --output <當次日期資料夾>`，並看 `latest_catalog_info.json` |
| `pending_novels` 是 0 個 | 可能官方只更新資源、或新文本已在既有來源、或翻譯記憶全部套用成功。仍要看 `l2d_changes.txt` 與 `new_folders_only\index.md` |
| 第 4 階段 `ExportCatalogNovelTexts.py` 丟 `FileNotFoundError`，但父目錄明明存在 | **2026-09-10 已從根本修掉**，正常情況不該再看到。原因是 **Windows 260 字元路徑上限**：劇本檔名很長（`general-novel_assets_assets_project_...`＋雜湊＋序號），輸出根放在 `Desktop\...` 底下就會超標，而 Windows 對過長路徑回報的正是 `FileNotFoundError`，完全不像長度問題。現在寫檔一律經過 `long_path()` 加 `\\?\` 前綴，不再受 260 限制，`-BaseDir` 也不必再遷就長度。踩過兩次（2026-08-20、2026-09-10），兩次都是同一支 `men_10010100001` 的 raw TXT，完整路徑 263 字元，機器的 `LongPathsEnabled` 是 0。若真的又出現，先確認跑的是修好後的版本 |
| `Missing bundles:` 是個大數字（例如 1161 = 全部） | **`--downloads` 指錯了**，不是下載失敗。下載目錄叫 **`text_novel_downloads`**，不是 `downloads`；下載真的失敗會寫進 `download_failed.txt`（正常是空的），而 `download_status.json` 會顯示 `failed: 0`。打開 `novel_missing_bundles.json` 看 `file_path`，就知道它去哪裡找。2026-09-10 手動重跑階段 4 時就是這樣誤判成「1161 顆全沒下載到」 |
| catalog 裡的劇本突然消失 | **不要連動刪除 repo**。官方可能只是撤下預載。保留上一版 `official_update_*`，記錄「上一版有、本版無」，等下次更新再判斷 |
| 階段 1 跑到一半整個 Python 被系統砍掉，`assets.json` 只有半截、`latest_catalog_info.json` 沒產生 | **記憶體不足**，2026-09-21 踩過（`assets.json` 只寫到 131,736,763／387,150,676 位元組）。原因是舊版會先把 12 萬筆 location 全展開成 dict 清單再 `json.dump`，階段 2、4 又各自 `json.loads(read_text())` 整份 390MB（實測峰值 1.1GB、解析完常駐 545MB）。**當天已改成串流**：`UnityCatalogReader.export_to_json` 逐筆序列化直接寫檔，階段 2／4 改用 `tools/json_stream.py` 的 `iter_json_array()` 逐筆讀，峰值降到 8MB 以內，輸出逐位元組不變。若又看到半截檔，先確認跑的是修好後的版本；真的是磁碟或網路斷掉，`iter_json_array()` 現在會明確丟「陣列在檔案結束前就中斷了」而不是默默少給資料 |
| 官方主機**全路徑** 403，內文 `Request blocked.`、`Generated by cloudfront` | 官方 WAF 認 **TLS 指紋**擋腳本，2026-09-21 出現。**不是網路、不是地區、不是頻率**：實測掛 VPNGate 東京 IP（`219.100.37.233`）照樣 403，但同一台機器同一秒 `curl.exe`（走 Schannel）回 200，換 UA／header 完全無效。`DotAbyss.py` 的 `TlsAdapter` 換掉 OpenSSL 預設 cipher 清單即可通過——對方是列黑名單不是白名單。若日後復發，先確認 `curl.exe` 是否也被擋：只擋 Python 就再調 cipher，連 curl 都擋才是真的改成白名單。**繞過措施的用途限制見 `README.md` 開頭，務必遵守** |

## 9. 每次交付前檢查表

```
□ 使用新日期資料夾，沒有覆蓋上一版
□ 記錄 AssetVersion、MasterDataVersion、catalog hash
□ 下載失敗 0、解包失敗 0
□ 檢查 pending_novels 與 new_folders_only
□ 檢查既有資料夾內的新 key，不能只看資料夾名稱
□ 只翻 zh_Hant.json 的 value
□ 譯名符合 names/zh_Hant.json
□ 空值、JSON parse error、tag error 都為 0
□ git diff 只含預期的小說與譯名檔
□ 不提交大型 catalog、bundle、下載目錄
□ 重要預載文本另存，避免下版撤下
□ 回上層跑 build_novels_all.py + update_manifest.py，push 後跑 verify_cdn.py
```

最後一項最常漏，而且漏了不會有任何錯誤訊息。
