# 遊戲文本在地化翻譯與校正指南

本文件是後續翻譯與校正遊戲劇情文本時必須遵守的規則。目標是將輸入文本（日文、簡中、簡轉繁或混合文本）轉化為高品質、自然流暢的台灣繁體中文。

## 最高優先級：系統與格式保留

- Key 值絕對不修改。JSON 的日文 Key、代碼、看似錯誤或奇怪的 Key 都必須保持原樣，除非使用者明確要求修 Key。
- 只修正 value。所有翻譯、潤飾、校正都只能動中文譯文 value。
- 控制碼與標記必須完美保留，包括但不限於 `<br>`、`<user>`、`<size=48>`、變數、顏色標籤、符號、數字、換行標記等。
- 控制碼不得漏刪、錯置、改寫或移位到不合語意的位置。
- 成人文本只修正翻譯品質，使其自然流暢、術語前後一致。嚴禁自行擴寫、加料或刪減情節。

### 專案固定例外

維持原文的是**三個欄位**，不是整張表：

```
m_character_abilities/name
m_character_action_skills/name
m_gacha_group_movies/skill_name
```

⚠️ **同表的 `m_character_action_skills/description` 是要翻的**（角色詳情／抽卡畫面的
主動技能說明）。2026-08-10 就是因為工具與本文件都寫成「整張表」，那一欄從來沒被抽出過，
每個新角色上線都是一片日文。詳見 `HANDOVER.md` 第 1-4 節。

二つ名（帶 `[LvN]` 的稱號）同樣維持原文。

紋章色標規則（`<color=#FF5050>紋章：情熱</color>` 等）在 `AGENTS.md`
「Permanent translation exclusions and emblem colors」。

> **`AGENTS.md` 是這兩條規則的唯一來源**：上面的欄位清單只是抄過來方便翻譯時查，
> 兩邊萬一不一致，一律以 `AGENTS.md` 為準，並且只改那一份。
> （2026-08-10 就是因為本檔留著「整張表禁翻」的舊寫法而漏譯了一整批。）

## 正式譯名表

- 專有名詞、角色名、稱號、地名與特定術語一律以本 repo 的 `names/zh_Hant.json` 為準。
- 若本文件的角色範例、過往口頭規則或腳本建議與 `names/zh_Hant.json` 不一致，一律以該檔為準。
- 若文本中出現表內 Key 對應內容，必須嚴格使用該表 value 作為譯名。
- 腳本產生任何 dry-run 或 write 建議前，必須先套用 `names/zh_Hant.json` 的正式譯名。
- `<user>` 必須保留為 `<user>`，不得翻譯。
- 改譯名時要連改組合 key，並注意不要無條件全域替換（`HANDOVER.md` 陷阱四、五）。

| 哪兒 | 哪裡 |

### UI 與系統詞彙

若文本包含 UI 或系統介面，依台灣用語修正：

| 避免用語 | 台灣繁中建議 |
| --- | --- |
| 視頻 | 影片 |
| 軟件 | 軟體 |
| 屏幕 | 螢幕 |
| 設置 | 設定 |
| 默認 | 預設 |
| 充值 | 儲值 |

### 繁簡與錯字修正

- `复製` 改為 `複製`。
- `工資` 依語境改為 `薪水`。
- `這裏`、`那裏` 統一改為 `這裡`、`那裡`。
- 統一使用 `裡`，不使用 `裏`。
- 依語境區分 `聯繫` 與 `聯絡`；人與人之間互動一律用 `聯絡`。

## 遊戲術語對照

角色名、道具名等專有名詞以 `names/zh_Hant.json` 為準；下表是**常見的一般術語**，
這些詞照日文漢字直搬會錯，逐條記住：

| 日文 | 中文 | 備註 |
|---|---|---|
| 厄災 | 災厄 | 語序相反 |
| 凶化厄災 | 凶化災厄 | 非「兇化」 |
| ランク（裝備） | Rank | 但 VIPランク／プレイヤーランク＝等級 |
| 浸食率／侵食率 | 侵蝕率 | 動詞用**增加／減少**，非上升／下降 |
| 会心 | 暴擊 | 非「會心」 |
| 回避率 | 閃避率 | |
| モンスター | 魔物 | 非「怪物」（原文另有 怪物／化け物 要保留） |
| 大穴 | 大洞窟 | 非大洞穴／巨穴 |
| 掃討 / 追跡 | 掃蕩 / 追蹤 | 日文漢字詞，中文不用 |
| マナ | 魔力 | 非「能量」 |
| ツルハシ / ピッケル | 十字鎬 | 兩詞共用同一中文 |
| エネミー | 敵方 | |
| 主人公 | 主角 | |

**數值增減標準**：上升／下降（⚠️ 但侵蝕率例外，用增加／減少）

⚠️ 補新句子前**先 grep 既有句式**再決定用詞——這一步最容易出錯，
理由與實例見 `HANDOVER.md` 第 2 節。

## 打破翻譯腔

- 嚴禁硬照日文句序排列。
- 避免生硬直譯，例如「在某某中出征」、「露出來」、「一股腦」等不自然組合。
- 若原始簡中、日文譯文語意邏輯混亂，或二轉手造成嚴重翻譯腔，必須在不改變核心劇情的前提下大膽重組句子。
- 第一優先是台灣繁中自然語感，其次才是逐字對應。

## 標點符號與排版

- 中國式雙引號 `“”` 必須改為台灣標準引號 `「」`。
- 中國式單引號 `‘’` 必須改為 `『』`。
- 英文句點連打 `......` 統一改為標準全形刪節號 `……`。
- 清理簡中轉繁時產生的不必要半形空格。
- 保持文本緊湊、自然，不加入無意義空白。

## 角色語氣與人設

所有對話必須符合人物設定，避免每個角色都像同一個人說話。

### 羅莎

- 語氣正式、嚴謹。
- 帶有騎士精神與榮譽感。
- 避免俚俗或過度口語。

### 貝麗莎

- 語氣撒嬌、可愛、黏人。
- 可帶活潑語尾，但不可過度加料。
- 需要保留角色原本的親暱感。

### 瑪麗娜

- 語氣精明、市儈、圓滑。
- 具有商人的算計與社交手腕。
- 可保留圓滑拖腔，但不可翻成平淡直白句。

### 主角內心吐槽

- 必須自然、幽默。
- 像一般年輕人的內心 OS。
- 不使用過度書面或生硬文字。

## 執行提醒

- 翻譯與校正時，必須同時檢查語意準確度、繁簡轉換、台灣在地化、角色語氣、控制碼保留。
- 若遇到原文或既有譯文混亂，必須在不改變核心劇情的原則下重新潤飾，使其符合台灣繁中自然語感。
- 若是 JSON，輸出與修改時必須保持合法 JSON 格式。
- Key 不動，value 才是工作範圍。
